# 시각 문서의 제작 경로

내용과 독자의 질문이 표현과 읽기 순서를 결정한다. Forge는 원문의 의미와 권위를 보존하고 요청한 결과를 검증하는 지침을 제공한다.

## Requirements

### Forge는 일반 시각화 요청을 전용 Visual Docs 제작 절차에 강제 라우팅하지 않아야 한다.

Forge 원문과 무관한 표, 도식과 시각화는 현재 앱 기능과 모델의 판단으로 처리한다.

### Forge 원문의 시각화는 독자와 내용에 맞는 표현을 선택하고 고정 시각 템플릿이나 전용 빌드 입력을 요구하지 않아야 한다.

대화 안의 표·Mermaid, 사용 가능한 시각화 도구, 직접 작성한 HTML·CSS·JavaScript를 사용할 수 있다. Brief 파일, Project Map, composition JSON, 고정 section·탐색 구조를 만들기 위해 원문을 재구성하지 않는다. Forge 배포에는 공통 시각 템플릿과 관리형 renderer 경로를 포함하지 않는다.

### Forge 원문의 시각화는 원문의 권위와 조건을 보존하고 요청한 결과의 의미와 표시를 검증해야 한다.

조건·예외·수치·책임·확정 상태와 Brief·Plan·Spec의 역할을 유지한다. 핵심 설명을 원문 링크나 필요한 인용에 연결하고 원문 사실, 추론과 예시를 구분한다. 근거 없는 정책·승인·의존성을 만들지 않는다. 파일 위치만으로 영역의 목적이나 소유권을 단정하지 않는다.

실제 제공 표면에서 핵심 질문에 답할 수 있는지, 중요한 조건이 드러나는지 확인한다. 문서에 해당하는 링크와 상호작용을 검사하고 복잡한 배치에는 좁은 화면도 확인한다. 생성 성공이나 출처 일치만으로 이해도와 시각 품질을 보장하지 않는다. 수행하지 못한 검증은 밝힌다.

### 기존 시각 문서의 갱신은 해당 문서의 제작 방식과 원문을 확인하고 내용과 유용한 상호작용을 보존해야 한다.

프로젝트가 관리하는 generator가 있으면 그 방식을 사용하고, 직접 작성한 문서는 직접 수정할 수 있다. 이전 Forge 관리형 문서도 요청에 따라 갱신할 수 있으나 제거된 builder를 호출하지 않는다. 수정한 산출물에서 더 이상 성립하지 않는 생성기·freshness 표시는 제거하거나 실제 검증 방식에 맞춘다. 별도 요청 없는 기존 산출물이나 전역 설치본은 삭제하지 않는다.

### 재현성이나 원문 최신성 검증을 요청하면 표현 형식과 독립적인 프로젝트별 방법으로 확인하고 실제 보장 범위를 보고해야 한다.

원문 revision·hash 비교나 보존한 작성 소스와 빌드 명령 등 요청에 맞는 방법을 사용한다. Forge 전용 manifest, schema나 화면을 요구하지 않는다. 확인하지 않은 자동 최신성이나 동일 입력 재생성을 보장하지 않는다.

반복 열람이나 인계에 필요한 출처·변경 추적은 화면과 독립적으로 제공한다. 선택형 source-context 도구나 기존 프로젝트 방법을 사용할 수 있다. 원문 hash와 설명 파일 hash를 함께 기록하면 각각의 변경을 구분할 수 있지만 의미의 정확성과 선택하지 않은 의존성은 별도로 검토한다. 이 기능의 범위는 [작업 컨텍스트와 읽기 쉬운 문서](../task-context-and-readable-documents/task-context-and-readable-documents.md)에 따른다.

### 완료된 시각 문서는 원문 변경만으로 자동 갱신하지 않아야 한다.

진행 중인 시각화 요청에는 필요한 수정과 검증이 포함된다. 일반 Spec·Plan 작업, 승인이나 checkpoint가 새 시각 문서 생성 요청을 대신하지 않는다. 이미 요청한 결과를 완성하기 위해 같은 의도를 다시 승인받지 않는다.
