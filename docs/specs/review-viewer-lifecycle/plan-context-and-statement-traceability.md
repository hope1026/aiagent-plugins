# Plan Context와 문장 추적성

계획은 목표를 실행하고 작업을 이어받는 데 필요한 기록이다. 내용과 관계를 읽으며, 특정 parser 문법을 요구하지 않는다.

## Requirements

### 계획은 목표와 다음 작업, 실제 의존성과 완료 판단을 설명해야 한다.

앱의 기존 기록, 체크리스트나 Markdown 문서를 사용할 수 있다. 파일을 남길 때는 프로젝트 관례나 내용에 맞는 docs/plans 경로를 선택한다. 번호가 붙은 디렉터리, Task·Step 제목, 고정 섹션과 필드 수를 강제하지 않는다.

### 계획은 작업에 필요한 계약과 조건을 원문에서 확인할 수 있도록 연결해야 한다.

관련 source 경로와 필요할 때의 section link를 사용한다. 링크 label은 이해하기 쉬운 설명으로 쓸 수 있고 적용 범위가 명확하면 공통 참조를 재사용한다. Related Specs나 Governing statements block, 모든 Task에서 요구사항 전문을 반복하는 형식과 별도의 Plan parser는 요구하지 않는다.

### 계획의 검증은 작업의 완료 주장과 영향 범위에 맞춰야 한다.

부분 변경은 영향받는 동작과 회귀를 확인하고, 전체 계약 구현 주장은 그 전체 범위를 확인한다. 계획에 관련된 계약이 있다고 새 정본을 만들거나 계획을 승인 권위로 취급하지 않는다. 구현과 승인된 의미가 다르면 드러내고 필요한 판단을 받는다.

### 계획의 상세 수준과 진행 기록은 실행과 복구에 필요한 만큼 선택해야 한다.

파일 경계, interface, 복구 지점과 추가 승인 정보는 실제로 필요한 작업에 포함한다. 도식은 명시된 관계를 이해하는 데 도움이 될 때 사용한다. 독립 소유권이나 인계에 도움이 되면 Task·progress 파일을 분리할 수 있다. 진행은 기존 기록을 재사용하고 삭제 전에 영구 결정은 정본이나 ADR 등에 보존한다.
