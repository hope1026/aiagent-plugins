# 적응형 실행 라우팅과 Checkpoint

## Documents

- root: [적응형 실행 라우팅과 Checkpoint](adaptive-execution-routing-and-checkpoints.md)

## Overview

실행 방식은 작업 시작 시 현재 목표와 앱의 기능에 맞춰 선택한다. 독립적으로 맡길 수 있는 작업은 위임 이득과 문맥 전달·통합 비용을 비교하고, 하위 작업마다 필요한 모델 역량과 추론 깊이를 판단한다. 공통 tier 점수, 고정 인원, 태스크마다의 정형 원장은 요구하지 않는다.

## Requirements

### Forge는 작업 독립성, 문맥 전달 비용, 검증 가능성과 사용자 설정을 고려해 실행 주체를 선택해야 한다.

작업 시작 시 위임 가능한 범위를 찾고, 서브에이전트가 지원되며 위임 이득이 전달·통합 비용보다 크면 해당 작업을 위임한다. 작거나 강하게 연결된 작업은 직접 처리한다. 위임할 때 필요한 문맥, 결과물, 수정 소유권과 검증 조건을 전달한다.

### 모델 선택과 동시 실행 수는 현재 플랫폼 기능과 사용자 권한·설정을 따르고 고정 tier나 인원 상한을 추가하지 않아야 한다.

사용자가 지정한 모델·effort와 상위 지침을 우선하고, 현재 환경이 노출하는 기능으로만 선택한다. 모델명이나 effort 지원값을 Forge 공통 지침에 고정하지 않는다. 설정 변경이 지원되지 않으면 현재 설정을 상속하고, 서브에이전트가 없으면 직접 수행한다. 위임을 위해 전역 설정을 바꾸거나 지원하지 않는 호출을 만들어내지 않는다.

### 설정 선택이 지원되고 허용되면 Agent는 하위 작업에 필요한 역량과 문맥 규모로 모델을, 추론 깊이·불확실성과 실패 영향으로 reasoning effort를 선택해야 한다.

선택한 모델이 지원하는 effort와 기본값을 기준으로 판단한다. 명확한 검색·반복 수정은 빠르고 가벼운 구성을, 일반 구현은 균형 잡힌 구성을, 복잡한 원인 분석·설계·중대한 실패 가능성 검토는 더 높은 역량이나 추론 깊이를 고려한다. 작업 난이도와 검증 가능성을 함께 판단하며, 같은 effort 이름을 모델 간 동일한 수준으로 취급하지 않는다. 이 예시는 고정 등급표나 최저 설정부터의 순차 승급 규칙이 아니다. 메인 Agent의 현재 모델을 전환할 수 있다는 가정도 하지 않는다.

### 병렬 작업은 의존성과 쓰기 소유권의 충돌을 해소하고 각 결과와 통합의 검증 방법을 갖춰야 한다.

### Root는 위임 결과와 실제 증거를 검토하고 현재 통합 상태에 적용되는 검증을 바탕으로 완료를 판단해야 한다.

### 진행 기록은 기존 계획이나 앱 기록을 재사용하고 재개에 필요한 결과·증거·미해결 선택만 보존해야 한다.

### Agent는 승인된 안전한 작업을 계속하고 새로운 사용자 선택이나 권한 밖 효과에 의존하는 행동만 중단해야 한다.

### 반복 시도가 새 증거를 만들지 못하면 가설과 방법을 재검토하고 확인되지 않은 결과를 완료로 보고하지 않아야 한다.

예상보다 복잡한 의존성, 새로운 불확실성, 검증 실패가 드러나면 작업 분해와 실행 주체, 모델·effort 선택을 재평가한다. 모델이나 effort를 높이는 것만으로 원인 분석이나 검증을 대신하지 않는다.

### Visual Docs는 사용자 요청이 있을 때만 생성하거나 갱신하며 실행 기록이나 정본을 대체하지 않아야 한다.

## Decisions & History

- 2026-09-24 [CURRENT] 작업 시작 시 위임 가능성을 판단하고 이득이 있는 독립 작업을 위임한다. 하위 작업별 모델과 effort는 현재 기능·권한·사용자 설정 안에서 각각 선택하며, 새 증거에 따라 재평가한다. 기능 미지원 시 상속 또는 직접 수행하고 고정 모델 등급표·인원·원장을 추가하지 않는다.
- 2026-09-10 위임은 조정 비용보다 이득이 있을 때 사용한다. 현재 상태에 적용되는 증거를 재사용하며 상세 route 기록과 모델 등급은 필요한 작업에서만 선택한다.
