# 적응형 실행 라우팅과 Checkpoint

## Documents

- root: [적응형 실행 라우팅과 Checkpoint](adaptive-execution-routing-and-checkpoints.md)

## Overview

실행 방식은 작업 시작 시 현재 목표와 앱의 기능에 맞춰 선택한다. 독립적으로 맡길 수 있는 작업은 위임 이득과 문맥 전달·통합 비용을 비교하고, 하위 작업마다 필요한 모델 역량과 추론 깊이를 판단한다. 공통 tier 점수, 고정 인원, 태스크마다의 정형 원장은 요구하지 않는다.

## Requirements

### Forge는 Git 저장소에서 새 작업을 시작하기 전에 사용할 워크트리의 변경사항과 다른 작업의 사용 여부를 확인해야 한다.

파일을 쓰거나 브랜치를 바꾸기 전에 메인 워크트리와 현재 워크트리의 위치, 사용할 워크트리에 체크아웃된 브랜치, 스테이징된 변경과 스테이징되지 않은 변경, 추적되지 않은 파일을 확인한다. 진행 중인 병합이나 리베이스도 확인한다. 앱에서 작업 중인 세션과 경로를 확인할 수 있으면 같은 워크트리를 쓰는 다른 작업이 있는지 살핀다. Git 상태에서 변경 파일이 없어도 다른 작업이 진행 중일 수 있다. 조회만 하는 요청이나 Git 밖에서 하는 작업에는 브랜치나 워크트리를 만들지 않는다.

### 새 작업은 깨끗하고 사용 가능한 메인 워크트리의 새 브랜치에서 시작하고, 메인 워크트리를 사용할 수 없으면 별도의 워크트리에서 시작해야 한다.

사용자가 작업 위치나 브랜치를 지정했거나 앱이 이미 해당 작업에 별도의 워크트리를 할당했다면 그 지정을 우선한다. 기본 브랜치의 적절한 커밋을 새 브랜치의 시작점으로 삼고, 현재 작업에 필요한 선행 커밋이나 저장소 규칙이 있으면 그 기준을 따른다. 메인 워크트리에 이전 변경사항이나 진행 중인 Git 작업이 있거나 다른 작업이 해당 경로를 사용 중이면, 기존 변경과 브랜치를 그대로 두고 이 작업에서 쓸 수 있는 깨끗한 별도 워크트리를 재사용하거나 만든다. 기존 변경 위에서 작업해야 하거나 안전한 별도 위치를 확보할 수 없을 때는 확인된 상태를 설명하고 필요한 선택만 사용자에게 묻는다.

### 같은 작업을 재개할 때는 기존 워크트리와 브랜치를 재사용하고 이 작업의 변경사항을 보존해야 한다.

재개할 때도 워크트리 상태를 확인한다. 이 작업에서 남긴 변경은 이어서 사용한다. 소유가 불명확한 변경이 새로 생겼거나 다른 작업도 같은 경로에 쓰고 있으면, 충돌을 피할 수 있는 위치를 선택하거나 필요한 부분을 사용자에게 확인한다. 워크트리를 비우기 위해 기존 변경을 자동으로 stash, reset, 삭제, 커밋 또는 이동하지 않는다.

### Forge는 작업 독립성, 문맥 전달 비용, 검증 가능성과 사용자 설정을 고려해 실행 주체를 선택해야 한다.

작업 시작 시 위임 가능한 범위를 찾고, 서브에이전트가 지원되며 위임 이득이 전달·통합 비용보다 크면 해당 작업을 위임한다. 작거나 강하게 연결된 작업은 직접 처리한다. 위임할 때 필요한 문맥, 결과물, 수정 소유권과 검증 조건을 전달한다.

### 실행 계획을 세웠다면 구현 전에 계획을 검토하고 타당한 피드백을 반영해야 한다.

세션에 작성한 계획과 파일로 저장한 계획 모두에 적용한다. 별도 에이전트를 사용할 수 있으면 작성자와 다른 에이전트에게 검토를 맡긴다. 사용자 설정을 따르면서 검토에 필요한 역량과 문맥 규모에 맞는 모델을 선택하고, 모델을 지정할 수 없으면 현재 설정을 상속한다. 별도 에이전트를 사용할 수 없으면 작성자가 같은 기준으로 직접 검토한다. 작성자는 검토 결과를 사용자 요청 및 정본 스펙에 대조하고 타당한 지적을 계획에 반영한 뒤 구현한다. 재개할 때는 현재 계획에 적용되는 리뷰를 재사용하고, 범위·의존성·검증 방법이 달라져 기존 리뷰가 다루지 못한 부분은 구현 전에 같은 절차로 다시 검토한다.

### 모델 선택과 동시 실행 수는 현재 플랫폼 기능과 사용자 권한·설정을 따르고 고정 tier나 인원 상한을 추가하지 않아야 한다.

사용자가 지정한 모델·effort와 상위 지침을 우선하고, 현재 환경이 노출하는 기능으로만 선택한다. 모델명이나 effort 지원값을 Forge 공통 지침에 고정하지 않는다. 설정 변경이 지원되지 않으면 현재 설정을 상속하고, 서브에이전트가 없으면 직접 수행한다. 위임을 위해 전역 설정을 바꾸거나 지원하지 않는 호출을 만들어내지 않는다.

### 설정 선택이 지원되고 허용되면 Agent는 하위 작업에 필요한 역량과 문맥 규모로 모델을, 추론 깊이·불확실성과 실패 영향으로 reasoning effort를 선택해야 한다.

선택한 모델이 지원하는 effort와 기본값을 기준으로 판단한다. 명확한 검색·반복 수정은 빠르고 가벼운 구성을, 일반 구현은 균형 잡힌 구성을, 복잡한 원인 분석·설계·중대한 실패 가능성 검토는 더 높은 역량이나 추론 깊이를 고려한다. 작업 난이도와 검증 가능성을 함께 판단하며, 같은 effort 이름을 모델 간 동일한 수준으로 취급하지 않는다. 이 예시는 고정 등급표나 최저 설정부터의 순차 승급 규칙이 아니다. 메인 Agent의 현재 모델을 전환할 수 있다는 가정도 하지 않는다.

### 병렬 작업은 의존성과 쓰기 소유권의 충돌을 해소하고 각 결과와 통합의 검증 방법을 갖춰야 한다.

### Root는 위임 결과와 실제 증거를 검토하고 현재 통합 상태에 적용되는 검증을 바탕으로 완료를 판단해야 한다.

### 진행 기록은 기존 계획이나 앱 기록을 재사용하고 재개에 필요한 결과·증거·미해결 선택만 보존해야 한다.

### Agent는 승인된 안전한 작업을 계속하고 새로운 사용자 선택이나 권한 밖 효과에 의존하는 행동만 중단해야 한다.

### 반복 시도가 새 증거를 만들지 못하면 가설과 방법을 재검토하고 확인되지 않은 결과를 완료로 보고하지 않아야 한다.

예상보다 복잡한 의존성, 새로운 불확실성, 검증 실패가 드러나면 작업 분해와 실행 주체, 모델·effort 선택을 재평가한다. 모델이나 effort를 높이는 것만으로 원인 분석이나 검증을 대신하지 않는다.

### Visual Docs는 사용자 요청이 있을 때만 생성하거나 갱신하며 실행 기록이나 정본을 대체하지 않아야 한다.

## Decisions & History

- 2026-11-28 [CURRENT] 새 Git 작업은 기존 작업이 남아 있지 않은 상태에서 시작한다. 기본 위치는 메인 워크트리이며, 변경사항이나 다른 작업 때문에 사용할 수 없으면 별도 워크트리에서 진행한다.
- 2026-11-17 [CURRENT] 실행 계획은 구현 전에 적합한 모델의 별도 에이전트가 검토하고, 별도 에이전트를 쓸 수 없으면 작성자가 직접 검토한다. 어느 경우든 타당한 피드백을 반영한다.
- 2026-09-24 작업 시작 시 위임 가능성을 판단하고 이득이 있는 독립 작업을 위임한다. 하위 작업별 모델과 effort는 현재 기능·권한·사용자 설정 안에서 각각 선택하며, 새 증거에 따라 재평가한다. 기능 미지원 시 상속 또는 직접 수행하고 고정 모델 등급표·인원·원장을 추가하지 않는다.
- 2026-09-10 위임은 조정 비용보다 이득이 있을 때 사용한다. 현재 상태에 적용되는 증거를 재사용하며 상세 route 기록과 모델 등급은 필요한 작업에서만 선택한다.
