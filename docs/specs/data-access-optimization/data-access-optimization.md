# DB·외부 요청 최적화

## Documents

- root: [DB·외부 요청 최적화](data-access-optimization.md)

## 목적과 범위

Forge는 DB·외부 API를 사용하는 구현이나 수정에서 현재 변경이 건드리는 호출 경로를 검토한다. 호출 수 감소와 지연 개선은 기존 동작·권한·정합성을 보존해야 한다. 모든 작업에 성능 감사, 새 캐시 계층이나 벤치마크를 요구하지 않는다.

공통 실행 지침은 `using-forge/references/data-access.md`에서 관리한다. 계획·실행·검증 스킬은 해당 지침을 참조하며 서비스별 캐시 유효 기간이나 재시도 횟수는 관련 프로젝트 계약을 따른다.

## Requirements

### Forge는 영향받는 호출 경로에서 동일한 조건의 읽기 재사용과 중복 조회 감소를 검토해야 한다.

상위 조회 결과를 하위 함수에 전달하거나 요청 범위 context에서 재사용하고, 같은 조건의 진행 중인 읽기도 공유할 수 있다. 재사용 조건에는 결과에 영향을 주는 사용자·테넌트·권한·환경·제공자·자료 ID·조회 조건·버전·트랜잭션 문맥을 반영한다. 같은 인자의 쓰기는 서로 다른 의도일 수 있으므로 읽기 공유와 멱등성을 구분한다. 실패·미확정 상태를 성공이나 자료 없음으로 바꾸지 않는다.

### Forge는 읽기 재사용 시 무효화와 최신 확인 및 원자적 보호를 보존해야 한다.

관련 쓰기, 권한·소유권·회수 변경과 트랜잭션 경계에서 이전 근거의 유효성을 재판단한다. 현재 권한·소유권·회수·잔액, commit 조건, 잠금·CAS·멱등성·필수 저장·감사·outbox는 소유 계약대로 유지한다. 응답 유실 후 쓰기 결과 확인을 중복 읽기로 제거하거나 결과가 불명확한 부수 효과를 맹목적으로 재시도하지 않는다. 요청 간 캐시로 확대하려면 수명·무효화·격리를 포함한 계약 변경 권한을 확인한다.

### Forge는 묶음 조회와 병렬화를 평가할 때 호출 수와 총 작업량 및 실패 의미를 구분해야 한다.

N+1, 필요한 필드와 범위, bulk·batch를 검토하고 DB binding·페이지·응답 크기 상한을 지킨다. 독립 호출만 제한된 동시성으로 실행하고 누락·일부 실패를 정상 빈 결과로 바꾸지 않는다. 병렬 실행이나 네트워크 왕복 감소가 SQL 문 수 또는 DB 작업량 감소를 뜻하지는 않는다.

### Forge는 하위 호출과 재시도에 상위 요청의 시간 예산과 취소 소유권을 적용해야 한다.

남은 deadline, 취소와 제공자의 backoff를 전파하고 함수마다 전체 시간 예산이나 중첩 재시도를 새로 부여하지 않는다. 공유 호출은 누가 취소할 수 있는지 구분해 한 소비자의 이탈이 다른 소비자의 작업을 잘못 중단하지 않도록 한다. 상위 요청의 취소는 해당 요청이 소유한 작업에 적용한다.

### Forge는 성능 개선 주장에 비교 가능한 실측과 영향받는 정확성 검증을 요구해야 한다.

동일한 입력·조건·측정 경계에서 변경 전후 물리 DB 왕복, SQL 문, 외부 호출·재시도 수와 소요 시간을 구분한다. 항목 수에 따른 증가와 동시 변경·오류·취소 경로를 변경 위험에 맞게 검증한다. 부분 경로·합성 지연을 전체 요청·운영 성능으로 보고하지 않고, 측정하지 못한 개선은 미확인으로 남긴다. 계측에 원문 키·토큰·개인정보를 남기지 않는다.

## Decisions & History

- 2026-10-30 [CURRENT] 요청 범위의 읽기 공유, 정확성 보존, 제한된 작업량과 공통 시간 예산을 조건부 지침으로 추가한다. 성능 주장은 실측 범위를 명시하며 모든 작업의 전면 성능 검사를 요구하지 않는다.
