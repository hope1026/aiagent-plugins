# 오류 식별과 원인 보존

## Documents

- root: [오류 식별과 원인 보존](error-identification-and-cause-preservation.md)

## 목적과 범위

API·DB·외부 서비스 오류를 공통 처리할 때도 호출자의 대응과 운영 진단에 필요한 실패 구분을 유지한다. 같은 사용자 메시지를 보여주더라도 오류 종류와 개별 발생 건을 추적할 수 있어야 한다.

`using-forge/references/error-handling.md`가 공통 실행 지침을 소유한다. 오류 처리 경로를 구현·변경·평가할 때 적용하며, 무관한 작업에 오류 체계 전면 개편이나 새 로깅 인프라를 요구하지 않는다. 프로젝트의 기존 명명·응답·진단 계약을 우선 사용한다.

## Requirements

### Forge는 오류를 처리하거나 변환할 때 호출자의 대응이나 운영 진단이 다른 실패를 구분할 수 있도록 보존해야 한다.

인증 만료, 권한 부족, 요청 제한, 연결 실패, 외부 응답 해석 실패 등을 하나의 일반 코드로만 남기지 않는다. 공통 handler나 공개 응답의 통합은 허용하되 내부의 의미 있는 구분은 유지한다. 예상하지 못한 오류는 fallback 코드와 진단 근거로 추적하고 성공·빈 결과·확정된 부재로 바꾸지 않는다.

### Forge는 오류 코드에 프로젝트의 일관된 명명 체계와 안정된 의미를 적용해야 한다.

같은 의미는 같은 코드를 사용하고 대응이나 진단이 다른 의미는 구분한다. 문구·위치가 바뀌었다고 코드를 바꾸거나 폐기한 코드를 다른 의미로 재사용하지 않는다. 모든 예외 발생 위치에 별도 코드를 만들거나 보편적인 접두사·숫자 형식을 강제하지 않는다. 기존 코드 정의 위치에서 발생 조건, 호출자 대응과 공개 범위를 확인할 수 있게 한다.

### Forge는 오류 종류를 나타내는 코드와 개별 요청이나 발생 건의 추적 정보를 구분해야 한다.

기존 request ID, trace ID 또는 동등한 진단 식별자를 관련 응답·로그·하위 호출과 연결한다. 같은 오류 코드가 반복돼도 해당 건의 근거를 찾을 수 있어야 하며 시간·요청 ID를 오류 코드에 섞어 새 코드로 만들지 않는다. 프로토콜과 실제 경계에 맞는 방법을 사용하며 전용 분산 추적 시스템을 요구하지 않는다.

### Forge는 오류를 감싸거나 매핑할 때 원인과 실패한 작업을 필요한 진단 정보로 보존해야 한다.

원본 예외와 원인 연결, 외부 서비스 코드·상태·요청 ID 등 존재하는 정보를 필요한 범위에서 연결한다. 제공되지 않은 원인을 추측하지 않고 fallback이나 다대일 매핑에서도 원인을 찾을 수 있게 한다. 여러 계층에서 같은 오류를 중복 기록하는 대신 기존 진단 경로를 활용할 수 있다.

### Forge는 사용자에게 공개하는 오류 정보와 접근이 통제된 진단 정보를 구분해야 한다.

공개 응답에 토큰·비밀·개인정보·내부 스택을 노출하지 않는다. 내부 기록도 민감값을 제거하고 필요한 문맥만 보존한다. 원인 보존이 원문 요청·응답 전체 저장을 뜻하지 않으며 표시 메시지는 여러 오류에서 같을 수 있다.

### Forge는 공개 오류 코드의 의미나 호출자 대응을 변경할 때 해당 계약과 소비자의 영향을 확인해야 한다.

공개 코드의 추가·삭제·의미 변경과 재시도·복구 대응의 변화는 영향을 받는 프로젝트의 계약 변경으로 다룬다. 기존 소비자와 승인된 호환·이전 요구를 확인하고 `writing-specs`를 적용한다. 내부 위치별 식별자 추가를 이유로 불필요한 정본 스펙을 만들지 않는다.

### Forge는 변경한 오류 처리 경로에서 대표적인 실패의 구분과 원인 및 추적 연결을 실제 결과로 검증해야 한다.

영향받는 매핑·공통 handler를 통과한 결과를 확인한다. 의미가 다른 대표 실패, 같은 의미가 다른 위치에서 발생하는 경우, 미분류 오류와 민감정보 노출 여부를 변경 범위에 맞게 선택한다. 코드 목록·문구 검사만으로 동작을 입증하지 않으며 기존 테스트나 작고 통제된 실패 주입을 활용한다. 새 테스트 프레임워크나 모든 실패 조합은 요구하지 않는다.

## Decisions & History

- 2026-11-01 [CURRENT] 오류 종류의 안정된 식별, 개별 발생 추적과 원인 보존을 조건부 구현 지침으로 추가한다. 공통 처리를 허용하면서 필요한 구분을 유지하고 공개 정보와 내부 진단의 경계를 검증한다.
