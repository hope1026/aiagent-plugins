# 이 작업은 어떤 원문을 기준으로 했을까?

Forge의 원문 추적 기능은 AI가 읽을 자료를 전달하고, 나중에 그 자료가 바뀌었는지 확인하는 데 사용합니다. 같은 원문을 사람이 이해할 수 있는 문서로 설명할 때도 활용할 수 있습니다. 문서의 제목이나 화면 모양을 정하지 않습니다.

예를 들어 초대 기능을 고칠 때는 초대 규칙, 권한과 예외, 관련 코드와 테스트를 확인해야 합니다. 필요한 파일을 고르는 것은 작업자의 판단입니다. 검색하고 읽는 것으로 충분하면 그대로 진행하면 됩니다. 다른 작업자에게 넘기거나 나중에 원문 변경을 확인해야 할 때 자료를 묶어 두면 유용합니다.

## 자료를 묶으면 무엇이 들어가나요?

선택한 텍스트 파일의 전체 내용, 저장소 안의 경로와 SHA-256이 JSON에 담깁니다. Markdown에 특별한 제목이나 metadata를 넣을 필요는 없습니다. 한국어 설명과 코드도 그대로 들어갑니다. 명시적으로 선택한 파일만 읽고 관련 파일을 자동으로 찾아 추가하지는 않습니다.

사람이 읽을 설명 파일도 함께 추적할 수 있습니다. 설명 파일을 artifact로 지정하면 경로와 hash만 기록합니다. 이렇게 하면 원문이 바뀌었는지와 설명 파일 자체가 바뀌었는지를 구분할 수 있습니다. Artifact의 형식은 Markdown, HTML 등에 제한되지 않습니다.

원문 내용이 포함되므로 다른 사람이나 시스템에 전달하기 전에 선택한 파일을 확인해야 합니다. 자격 증명이나 무관한 민감 정보는 포함하지 않습니다.

## 변경 확인 결과를 어떻게 해석하나요?

| 결과 | 뜻 | 다음 판단 |
|---|---|---|
| `unchanged` | 기록한 파일의 bytes가 모두 같습니다. | 이전 근거를 재사용할 수 있는지 작업 맥락을 확인합니다. |
| `changed` | 선택한 파일 중 하나 이상이 달라졌습니다. | 변경된 원문이나 설명을 다시 읽어 영향을 판단합니다. |
| `unavailable` | 선택한 파일이 없거나 읽을 수 없습니다. | 파일별 결과에서 `missing` 또는 `unavailable`을 확인합니다. |

검사는 원문·설명·snapshot을 수정하지 않습니다. 변경된 문서를 자동으로 다시 생성하지도 않습니다. 바뀐 파일이 여러 개면 각 파일의 결과를 함께 제공합니다.

`unchanged`는 선택한 파일이 같다는 뜻입니다. 설명이 정확하거나 승인됐다는 뜻은 아닙니다. 빠뜨린 권한 문서나 새로 생긴 의존성은 검사하지 않으므로 전체 프로젝트가 같다는 뜻도 아닙니다. 다른 저장소 root를 지정하면 그 root의 같은 상대 경로와 비교하며 저장소의 신원을 인증하지 않습니다.

원문이 바뀐 뒤 설명을 검토하지 않고 snapshot만 새로 만들면, 새 hash가 있어도 설명은 틀릴 수 있습니다. 변경된 내용을 읽고 설명이 여전히 맞는지 확인하고, 맞지 않는 설명은 수정한 뒤 기록을 갱신해야 합니다. 문장 순서나 띄어쓰기만 달라져도 bytes 비교는 변경을 보고합니다. 의미가 바뀌었는지는 별도로 판단합니다.

## 실제 사용

아래 명령은 이 저장소에서 제공하는 도구를 실행합니다. 설치본에서는 `using-forge` 스킬의 `scripts/source_context.py` 경로를 사용합니다. Python 표준 라이브러리만 필요합니다.

```bash
python3 plugins/forge/skills/using-forge/scripts/source_context.py --repo-root . capture \
  --task "원문 추적 기능의 동작과 한계 검토" \
  --source docs/specs/task-context-and-readable-documents/task-context-and-readable-documents.md \
  --source plugins/forge/skills/using-forge/scripts/source_context.py \
  --artifact docs/guides/source-context.md
```

결과는 표준 출력에 나오며 파일을 자동 생성하지 않습니다. 나중에 비교할 필요가 있으면 JSON 출력을 작업 기록에 저장합니다. 저장소 안의 `.forge/work/<work-id>/context.json` 같은 경로를 사용할 수 있습니다.

```bash
python3 plugins/forge/skills/using-forge/scripts/source_context.py --repo-root . check \
  --snapshot .forge/work/<work-id>/context.json
```

종료 코드는 모두 동일하면 `0`, 파일 변경·삭제·읽기 실패가 있으면 `1`, 잘못된 입력이나 snapshot이면 `2`입니다. 잘못된 snapshot에는 schema 오류, 중복 경로, 원문 내용과 기록된 hash의 불일치가 포함됩니다.

기본 한도는 원문 파일 하나당 256 KiB, 전체 1 MiB입니다. 넘으면 일부를 자르는 대신 수집 전체가 실패합니다. `--max-source-bytes`와 `--max-total-bytes`로 한도를 조정할 수 있습니다. 이 값은 bytes 기준이며 AI가 충분한 컨텍스트를 받았는지 판단하는 점수는 아닙니다.

경로는 저장소 기준 상대 경로를 사용합니다. 저장소 밖 파일과 symlink 별칭은 읽지 않습니다. Symlink를 사용하고 있었다면 저장소 안의 실제 파일 경로를 지정합니다.

## 작업과 문서에서 지켜야 할 구분

원문은 승인된 정책일 수도 있고 현재 코드나 테스트일 수도 있습니다. Snapshot이 파일을 담았다는 사실이 그 파일을 정본으로 만들지는 않습니다. 정책과 구현이 다르면 무엇이 승인된 의도이고 무엇이 현재 구현인지 드러내야 합니다. 실제 결과를 테스트하거나 관찰해야 구현 상태를 말할 수 있습니다.

사람용 설명은 목적과 동작, 변경 영향, 중요한 예외를 독자가 이해하도록 구성합니다. AI용 컨텍스트는 그 작업에 필요한 조건과 근거를 선택합니다. 둘 다 같은 원문을 참조하며 설명이나 요약이 원문을 대신해 새로운 정책을 만들지 않습니다.

이 기능의 계약은 [작업 컨텍스트와 읽기 쉬운 문서](../specs/task-context-and-readable-documents/task-context-and-readable-documents.md)에 있습니다. CLI와 출력 검사는 bytes와 입력 형식을 확인합니다. 실제 작업 정확성과 독자의 이해는 별도 평가 대상입니다.
