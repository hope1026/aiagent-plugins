# UI 일관성과 안전한 조작 지침 검증

2026-11-05. 사용자가 [최종 계획](../plans/ui-consistency-and-safe-interactions.md)의 수정·배포와 현재 디바이스 업데이트를 승인했다. 배포 대상은 Forge 0.1.34다. 이 변경은 Forge 지침이며 위피 애플리케이션의 CSS·컴포넌트나 운영 데이터를 수정하지 않는다.

## 적용 범위

`using-forge/references/ui-work.md`를 공통 원문으로 추가했다. 제품 컨셉과 역할별 일관성, 단계적 정보 노출, 사용 불가 이유와 접근 가능한 설정 경로, 위험 작업의 명시적 확인을 다룬다. 계획·실행·검증은 이 원문을 참조한다. `ui-verification.md`는 렌더링·상태 전환·설정 왕복·확인/취소·실패 복구의 관찰에 집중한다.

두 UI 정본은 승인된 의미를 반영하고 기존 approved 상태를 유지한다. 이번에 전체 bundle이나 모든 플랫폼의 구현을 완료했다고 주장하지 않는다. 기존 draft·focus·scroll·subscription, 재정렬·저장 실패·접근성·전문 디자인 스킬 비필수 조건은 보존했다. 고정 픽셀·템플릿·매 작업의 승인 질문·전수 UI 감사는 추가하지 않았다.

## 독립 검토와 행동 평가

별도 문맥의 에이전트가 maintainer 지침·변경 스펙·스킬·참고 문서·계획을 읽었다. 권한 제한 Acceptance가 설정/재시도만 열거해 권한 요청 경로를 빠뜨린 문제를 발견했고, 해당 문구를 수정한 뒤 재검토에서 남은 수정 필요 사항이 없었다. 작은 native 변경과 브라우저 부재, 이미 충분한 최종 확인, 권한 부족과 확인 실패의 구분은 정적 의미 검토로 확인했다. 실제 native 실행 증거는 아니다.

별도 에이전트에게 공통 원문과 UI 검증 지침을 제공하고, 기한 압력과 잘못된 기존 스타일 복사 또는 위험 확인 생략 요구가 있는 작업을 수행하게 했다. 모델 override 없이 같은 환경을 사용했다. 임시 산출물은 `.forge/scratch/ui-release/` 아래에만 작성했고 제품 코드나 운영 API는 사용하지 않았다.

### 역할별 스타일과 정보 노출

`style-case/index.html`은 보고서 내보내기 화면이다. 기존의12px `!important`, 일반 버튼32px/36px, 주요 버튼16px 선언 충돌을 역할별 base/variant로 정리했다. Chromium148에서 본문14px, 섹션16px, 보조 버튼 두 개40px/14px, 주요 버튼44px/16px을 측정했다. 이 수치는 시나리오가 지정한 제품 기준이며 Forge 기본값이 아니다.

비용2·사용 가능10·예상 잔액8을 실행 전에 표시하고, 형식과 진단 정보는 실행 아래의 명확한 disclosure에 배치했다. 실제 키보드 열기/닫기·포커스, 날짜 변경 보존, 합성 CSV 다운로드, 잘못된 날짜의 실행 방지/복구,375px에서 긴 ID와 상세의 가로 넘침 방지를 확인했다. JavaScript 오류는 없었다. 부모 에이전트가 테스트 코드·evidence.json과 데스크톱 렌더링을 직접 검토했다.

재현 명령: `node .forge/scratch/ui-release/style-case/verify.mjs`. 기존 위피 저장소의 Playwright를 사용했으며 의존성을 설치하지 않았다. 실제 과금·서버 인가·실제 보고서 데이터, 다른 엔진·스크린리더·이 사례의200% 확대는 검증 범위가 아니다.

### 기존 지침과 같은 요청의 비교

baseline commit `519e70ce043ccf639a7d92e00f3b83e84d567a23`의 스킬을 별도 디렉터리로 추출하고, 새 문맥의 동일 모델·환경 에이전트에게 같은 스타일 작업을 제공했다. 기존 지침 사례도 body14px·제목16px·보조40px·주요16px/46px, 필수 비용 노출과 상세 분리, 날짜 오류·다운로드·모바일·키보드 검증을 충족했다. 마지막 시각 검사에서 비활성 hover 문제를 발견해 수정하고 재검증했다. 부모가 결과·스크립트·렌더링을 검토했다.

기존/변경 지침 모두 이 사례를 통과했으므로 새 지침의 상대적 성능 향상이나 재발 방지를 입증했다고 주장하지 않는다. 확인한 결과는 새 원문이 기존 자유도·검증 행동을 유지하면서 요구한 판단과 상태 경로를 명시적으로 연결한다는 것이다. 선행 조건/삭제 사례는 변경 지침에서만 수행했고 native·브라우저 부재 등은 독립 정적 검토로 평가했다. 모든 시나리오의 전후 실험을 수행한 것은 아니다. baseline 산출물은 `.forge/scratch/ui-release/style-baseline-case/`에 있다.

### 선행 조건과 위험 작업

`state-case/index.html`은 로컬 서비스 설정과 영구 삭제 fixture다. `verification-results.json`의30개 확인 항목이 통과했다. 준비 조건 부족에서 실행은 비활성이지만 이유와 연결 설정은 발견 가능했다. 설정 취소/완료 왕복에 제목 초안이 유지되고, 연결 후 실행이 가능했다. 설정 권한이 없으면 접근 불가능한 설정 대신 관리자 요청 경로를 제공했다. 확인 중·확인 실패·미설정은 서로 다른 문구와 행동을 제공했다.

기존 최종 확인 페이지 한 개에 대상·모든 보고서 손실·복구 불가를 표시했다. 초기 초점의 Enter, Escape와 취소는 삭제 명령0건이었다. 확정 후 중복 실행을 막았고, 전송 후 페이지 이탈을 취소로 표시하지 않았다. 확정 성공·실패·결과 미확정을 구분했으며 미확정은 새 삭제 없이 상태 조회로 확인했다. 되돌릴 수 있는 표시 토글에는 확인을 추가하지 않았다.

390px 가로 넘침, 터치로 관리자 안내 진입, root 글자 크기200%에서 넘침과 설정 조작 노출을 확인했다. 부모 에이전트가 검증 코드·결과와 삭제 확인 렌더링을 직접 검토했다. 재현 명령: `node .forge/scratch/ui-release/state-case/verify.cjs`. 합성 명령 로그이며 서버 인가·동시성·실제 삭제·native 동작이나 완전한 접근성 적합성을 증명하지 않는다.
